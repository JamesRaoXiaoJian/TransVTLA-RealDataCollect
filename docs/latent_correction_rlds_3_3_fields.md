## Version Strategy

The conversion does not overwrite `3.1.0` or `3.2.0`.

- `3.1.0`: point cloud fields only.
- `3.2.0`: point cloud plus contact fields.
- `3.3.0_candidate`: point cloud, contact fields, `gripper_xyz`, and `current_timestep`.
- `3.3.0`: symlink to `3.3.0_candidate` for standard TFDS/MLA dataloader reads.

## Field Generation Rules

### point_cloud

Generated by `scripts/add_pointcloud_to_rlds.py`.

Source:

- `steps/observation/primary_depth`
- `world_camera` intrinsics and extrinsics from `fuser/camera.py`

Rule:

1. Convert depth to meters with `depth_scale`.
2. Back-project pixels into the camera optical frame with intrinsics `K`.
3. Transform the selected points to robot base / TransVTLA world-base with `world_camera` `R/t`.
4. Save `point_cloud` as `float32 [1024, 3]`.
5. Save `next_point_cloud` as the next timestep's cloud, with the terminal step repeating the final cloud.

Frame and unit:

- Frame: robot base / TransVTLA world-base.
- Unit: meter.

### contact_memory

Generated by `scripts/add_contact_memory_to_rlds.py`.

Source:

- original `pressure/pressure.csv`, located through each episode's metadata source path
- aligned visual/pressure timesteps from `aligned_timesteps.csv`
- tactile calibration from `fuser/gripper_touch.py`

Rule:

1. Estimate the pressure baseline/noise from the early window.
2. Use dynamic per-region thresholds to suppress sensor drift and small offset bias.
3. Require stable contact evidence across adjacent frames.
4. Use region/channel strength and tactile geometry to generate contact xyz.
5. Maintain a causal contact memory of shape `[6, 3]` per timestep.
6. Write companion fields:
   - `valid_contact_mask`: `int64 [6]`
   - `contact_type`: `int64 [6]`, active contact slots are type 0, grasp slots are type 1
   - `contact_reliability`: `float32 [6]`
   - `contact_time`: `int64 [6]`, never greater than `current_timestep`

Frame and unit:

- Frame: robot base / TransVTLA world-base.
- Unit: meter.

### gripper_xyz

Generated by `scripts/add_lc_required_fields_to_rlds.py`.

Rule:

- `gripper_xyz = observation["state"][:3]`

The real dataset builds `state` from `robot_state.csv` columns `pose_1..pose_6` plus gripper position, so `state[:3]` is the robot pose position in base/world coordinates. This follows the current TransVTLA/MLA side convention for `gripper_xyz`.

Caveat:

- This is the robot pose position already present in `state`, not an additional fingertip center computed with a new `T_flange_gripper` offset.

Frame and unit:

- Frame: robot base / TransVTLA world-base.
- Unit: meter.

### current_timestep

Generated by `scripts/add_lc_required_fields_to_rlds.py`.

Rule:

- `current_timestep = 0, 1, ..., T - 1` inside each episode.

This is the visual/RLDS step index used for causal contact checks.

## Coordinate Frame Conclusion

The current 3.3.0 candidate uses one canonical xyz frame for the fields required by Latent Correction:

`robot_base / TransVTLA world-base`, unit `meter`.

Field summary:

| Field | Shape | Frame | Unit | Source |
| --- | --- | --- | --- | --- |
| `point_cloud` | `[1024, 3]` | robot base / TransVTLA world-base | meter | primary depth + world camera K/R/t |
| `next_point_cloud` | `[1024, 3]` | robot base / TransVTLA world-base | meter | shifted `point_cloud` |
| `contact_memory` | `[6, 3]` | robot base / TransVTLA world-base | meter | pressure + tactile calibration + aligned timestep |
| `gripper_xyz` | `[3]` | robot base / TransVTLA world-base | meter | `state[:3]` |

No additional frame alignment is required before using these fields together, assuming the model/projection code continues to expect base/world xyz and applies `world_camera` extrinsics only during projection.
